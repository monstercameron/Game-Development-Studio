# Interface translation (i18n)

Forge's interface text can be shown in other languages. The English text stays in the code, so a missing translation is harmless: it falls back to English. Optional machine translation with OpenAI fills in a language one page at a time, only when you ask and after you review what will be sent.

This guide covers the architecture and rules. Agents converting a file should follow the shorter [conversion guide](I18N_CONVERSION_GUIDE.md).

## Architecture

```
src/i18n/
  index.js            public API: import from './i18n/index.js' (always with the file name)
  i18n-core.js        store: locale, lazy catalogs, t/tp, formatters, reverse map (no React)
  i18n-react.js       useT(), <T>, I18nProvider, useLocale() (no JSX, loads in plain Node)
  message-format.js   {placeholder} and <tag> syntax, pseudo-locale, tooltip keys
  namespaces.js       namespace list, key pattern, page -> namespaces
  shipped-catalogs.js import.meta.glob of locales/<lang>/<ns>.json (only main.jsx imports it)
  languages.js        language list and BCP 47 checks for the translate dialog
  i18n-api.js         client for /api/i18n
  LanguageMenu.jsx, TranslatePageDialog.jsx, language-menu.css
  locales/en/<ns>.json   generated English catalog (source of truth for the server)
  manifest.json          generated: hash, kind and files per key
tools/i18n-extract.mjs, tools/i18n-scan.mjs, tools/i18n-ast.mjs
runtime/i18n-service.js  /api/i18n routes (registered in vite.config.js and runtime/http-server.js)
runtime/i18n-catalog.js  reads the shipped English catalog; sourceHash()
runtime/i18n-translate.js request building, chunking and response validation
runtime/i18n-store.js    .forge-runtime/i18n.sqlite
runtime/i18n-glossary.js protected product names and per-language terms
```

**Lookup.** `t(key, english, params)` returns, in order: a personal override, a shipped translation, a machine translation, or the English default. A catalog entry that carries the English `source` it was translated from is used only while that source equals the current English default, so editing English text in code never shows an outdated translation.

**English and no provider.** The default locale is `en`. In English no catalog is loaded and `t` returns the interpolated default, byte for byte. Components work without `I18nProvider`, which keeps every existing jsdom test valid.

**Lazy loading.** The first `t()` call for a namespace in a non-English locale starts loading `<namespace>` for that locale (shipped JSON via dynamic import, then cached machine translations and overrides from `/api/i18n/catalog`). Until it arrives, English is shown; then every component using `useT()` re-renders. A page loads only its own namespaces plus the shared ones. A failed load leaves English in place.

**Provider.** `I18nProvider` (wired in `src/main.jsx`) restores the saved language (browser `localStorage` key `forge-locale`, or the studio setting from `GET /api/i18n/preference` when the browser has none), configures the catalog loaders, and keeps `<html lang dir>` in sync. Choosing a language saves it in both places.

**Right-to-left.** `ar`, `he`, `fa`, `ur` (and other RTL scripts reported by `Intl.Locale`) set `dir="rtl"` on `<html>`. Checklist for CSS in new or converted components:

- Use logical properties: `margin-inline-start`, `padding-inline`, `inset-inline-end`, `border-inline-start`, `text-align: start`.
- Do not hard-code `left`/`right` for layout. Directional icons (arrows, chevrons) may need `transform: scaleX(-1)` under `[dir='rtl']`.
- Keep numbers, code, file names and model ids in their own element; add `dir="ltr"` to inputs that hold paths, URLs or code.
- Test with `ar` and with the pseudo-locale for overflow.

## API

```js
import { T, formatNumber, t, tp, useT } from './i18n/index.js';

// Components (re-render on language change; the functions are stable):
const { t, tp, formatNumber, formatDate, formatRelativeTime, formatList, formatDuration, locale } =
  useT();
t('queue.list.empty', 'No renders yet.');
t('queue.item.eta', 'About {minutes} min left', { minutes });
tp('queue.list.count', jobs.length, { one: '{count} render', other: '{count} renders' });
<T
  id="settings.keys.help"
  en="Add a key under <b>API keys</b> or read the <link>guide</link>."
  components={{ b: <strong />, link: <a href="/docs" /> }}
  params={{ name }}
/>;

// Helper modules: import the plain functions and call them when the text is shown.
export function emptyMessage() {
  return t('queue.list.empty', 'No renders yet.');
}
```

- **Placeholders** are `{name}` with an identifier name. Values are inserted with `String(value)`; numbers are not reformatted, so converted code shows exactly the text it showed before. Use `formatNumber()` only where the old code already formatted numbers. A missing parameter leaves `{name}` visible. Other braces are literal text.
- **Escaping.** Text is always rendered by React as text. Never use `dangerouslySetInnerHTML` for translations; a parameter containing `<b>` stays literal text.
- **Plurals.** `tp(key, count, forms, params)` picks a CLDR form with `Intl.PluralRules`; English needs `one` and `other`. `{count}` is filled with `String(count)` unless `params.count` is given (for example a formatted number). Translations provide the categories their language needs (`one/few/many/other` in Polish, six in Arabic). For a special zero message use a separate key and a condition.
- **Rich text.** `<T>` parses `<tag>…</tag>` and `<tag/>` in the translated text and renders `components[tag]` with the inner content as children (a self-closing tag keeps the element's own children). Unknown tags render their text only. Parameters in `<T>` may be React elements.
- **Formatting.** `formatNumber(value, options)`, `formatDate(value, options)` (default medium date, short time; returns `''` for invalid dates), `formatRelativeTime(value, unit)`, `formatList(items)` and `formatDuration(seconds, { style })` (hours, minutes, seconds; `''` for unknown values). In English they use the browser's own locale (`undefined`), so replacing `toLocaleString()` with them, using the same options, changes nothing for English users; in other languages they use the chosen language.
- **Locale controls.** `useLocale()` returns `{ locale, dir, setLocale, showOriginal, setShowOriginal, reloadCatalogs }`. `i18n.englishFor(text)` maps a shown translation back to its English source.

## Keys and namespaces

A key is `<namespace>.<component>.<name>` (up to two more segments), for example `models.forceStop.confirmTitle`. Segments after the namespace are code identifiers (`[A-Za-z][A-Za-z0-9_]*`).

- **Namespace** is the page or area id from `src/i18n/namespaces.js`: the route sections (`overview`, `chat`, `images`, `3d`, `vegetation`, `world`, `motion`, `video`, `music`, `sfx`, `voices`, `segmentation`, `game`, `queue`, `assets`, `megascans`, `models`, `diagnostics`) and the shared areas `common` (widgets and actions used on several pages), `shell` (navigation, top bar, main frame), `settings` (Settings dialog), `errors` (Errors review), `projects`, `viewer` (3D/asset viewers) and `i18n` (the language UI). "Translate this page" translates the page namespace plus `shell`, `common`, `settings`, `errors` and `i18n`.
- **Component** names the component or area (`forceStop`, `queueItem`, `powerSettings`).
- **Name** says what the text is (`title`, `saveButton`, `emptyState`, `errorTooLarge`).
- Generic words with identical meaning share `common.action.*` (`common.action.cancel`, `common.action.done`, `common.action.close`, `common.action.save`, `common.action.delete`, `common.action.retry`).
- Keys are stable ids. Keep the key when you only reword the English (the extractor updates the catalog and the server retranslates the changed string). Use a new key when the meaning changes.
- The same key must always have the same English default (`npm run i18n:check` fails otherwise).
- Keys must be string literals: no template literals, concatenation or variables, so the extractor can find every string. For a value-to-label map use getters (see the conversion guide).
- Tooltip keys are generated: `<section>.tooltip.<slug>_<hash>` from the label in `src/tooltips/pages/<section>.js`.

## What to translate

Visible text and text read by assistive technology: JSX text, `aria-label`, `aria-description`, `title`, `placeholder`, `alt`, `label` props, notices and validation messages set from the browser, empty and loading states, confirmation text, button text, units written as words ("minutes"), tooltips.

## What is never translated

- Class names, ids, `data-*` values, CSS, keys, `htmlFor`, `name`, `type`, `role`.
- URLs, routes, route and query parameters, file names and extensions, MIME types.
- Persisted or sent values: queue job types, model ids, enum values, option `value`s, JSON/HTTP/MCP fields, localStorage values, filenames written to projects. Translate only the label that displays such a value.
- Log lines, `console.*`, error reports sent to `/api/errors`, telemetry, test ids.
- Unit symbols (`MiB`, `px`, `ms`, `fps`, `°`), numbers, product, model and format names (Forge, GPU, CUDA, TRELLIS.2, Hunyuan3D, PNG...).
- User content: prompts, project and asset names, chat text, model output.
- Backend error messages. The studio services return English error strings that the UI shows as received (for example `ForceStopDialog`'s `error` prop or `reason.message` from a failed request). They pass through unchanged in phase 1; translating them needs stable error codes from each service and is a separate change.

## Field help and tooltips

`src/tooltips/FieldHelp.jsx` finds each control's label text and looks it up in `src/tooltips/pages/<section>.js`, which is keyed by the **English** label. When labels are translated, the store keeps a reverse map from every string `t()` produced to its English source (`i18n.englishFor`), and FieldHelp maps each label text node back to English before the lookup. The tooltip text itself is translated with the generated tooltip key, and the help button's accessible name uses the visible (translated) label. Consequences for conversions:

- A label converted with `t()` keeps its tooltip automatically. Keep the English default identical to the tooltip key in `src/tooltips/pages/*.js`; if you change one, change the other.
- Keep labels as their own text node: `<label>{t('images.form.seed', 'Seed')} <span>OPTIONAL</span>…`. Concatenating a label with other text in one string breaks the mapping.
- Tooltip pages stay English source files; do not wrap them in `t()`. The extractor reads them.

## Tooling

| Command                             | Purpose                                                                                                                                                                                                                                                                                                     |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run i18n:scan -- src/Foo.jsx`  | Lists unwrapped user-visible English with line numbers and kinds (`jsx-text`, `attribute`, `jsx-expression`, `message`, `error-message`, `property`, `sentence`, `returned-text`). Exit 1 when anything is found; `--report` always exits 0; `--json` for tools. Without files it summarizes all of `src/`. |
| `npm run i18n:check -- src/Foo.jsx` | Checks the calls in the given files (keys, static defaults, plurals, tags, duplicates against all other sources) and prints the keys found. Writes nothing.                                                                                                                                                 |
| `npm run i18n:check`                | Whole-repository check: fails on any error or when the generated catalogs are out of date.                                                                                                                                                                                                                  |
| `npm run i18n:extract`              | Regenerates `src/i18n/locales/en/*.json` and `src/i18n/manifest.json` (atomic writes; refuses to write when there are errors).                                                                                                                                                                              |

A deliberate exception to the scanner is a comment containing `i18n-ignore` with a reason, on the same line or the line above. Run `npm run i18n:extract` once after a batch of conversions (not from many agents in parallel); the server translates only strings present in the generated English catalog.

## Pseudo-locale

`en-XA` shows every converted string accented, about 40% longer and in brackets (`[Šåṽé ···]`), while placeholders and tags stay intact. Text that stays plain English is not converted; text whose closing bracket is cut off overflows. It is offered in the language menu only in development builds (`import.meta.env.DEV`) or on the Diagnostics page.

## Machine translation with OpenAI

Open the language menu (top bar) and choose **Translate this page with ChatGPT…**. The dialog (URL `?dialog=translate`):

1. Choose a language from the searchable list or type a BCP 47 code; it is checked with `Intl.getCanonicalLocales` and `Intl.DisplayNames`. English and the pseudo-locale are refused.
2. **What will be sent** shows the number of strings and characters, the number of requests, the model id and the per-section counts (translated, English changed, not translated, your edits). Only Forge's own interface text from the shipped English catalog is sent; projects, prompts, file names, assets and anything typed are never sent.
3. **Send to OpenAI** or cancel. Nothing is sent automatically or in the background. Progress is announced in a live region; cancelling (or closing the dialog) stops the remaining requests and keeps finished ones.
4. A report such as "212 strings translated, 3 kept in English: placeholder mismatch (2), rich-text tag mismatch (1)". Rejected strings stay English and are retried on the next run.
5. **Use <language>** switches the studio. Translated pages show a "Machine translated" flag with the model in its tooltip and a one-click **Show original English** toggle.

The same dialog offers **Review and edit strings** (manual overrides for single strings, kept when the page is translated again; plural strings are read-only there for now), **Reset translation for this page** (removes machine translations of the page's sections, keeps your edits) and **Delete language** (removes all its translations and edits), each with a confirmation. Translations work offline from the cache once stored.

### Settings

The model comes from Settings, **AI assist**, entry **Interface translation** (`ui-translate`, default provider OpenAI, model `gpt-6-luna`), stored in `.forge-runtime/settings.sqlite` with the other AI features. **Check model** asks OpenAI whether the key can use the model. The local provider is not supported for this feature; translation is refused with an explanation. The OpenAI key comes from the encrypted credential store (Settings, API keys); it is never read from an environment variable and never sent to the browser.

### Routes (`/api/i18n`)

All routes require a loopback `Host`. `POST` and `DELETE` also require `Origin` equal to the studio origin and `X-Forge-Request: i18n`; unknown request fields are rejected.

| Route                    | Purpose                                                                                                                                                                                                                                                   |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /languages`         | Languages with stored translations, the English namespaces, model, provider, whether a key is saved.                                                                                                                                                      |
| `GET /catalog?lang=&ns=` | Served entries `{ value, source, kind: 'machine' \| 'override', model }`, machine details and counts.                                                                                                                                                     |
| `GET /strings?lang=&ns=` | English and current value of every string, for review.                                                                                                                                                                                                    |
| `GET`/`POST /preference` | The saved interface language (`{ locale }`).                                                                                                                                                                                                              |
| `POST /preview`          | `{ lang, namespaces }` → counts, characters, requests, model, notice and a digest of exactly what will be sent.                                                                                                                                           |
| `POST /translate`        | `{ lang, namespaces, digest }` → NDJSON stream: `start`, `progress`, then `done` with the report (or `error`). 409 if the preview changed or another translation runs; 400 `no_key` or `provider_unsupported`; 429 when the hourly limit (30) is reached. |
| `POST /override`         | `{ lang, key, value }` saves a validated personal translation; `value: null` removes it.                                                                                                                                                                  |
| `DELETE /cache`          | `{ lang, namespaces?, includeOverrides?, confirm: 'delete' }` resets a page or deletes a language.                                                                                                                                                        |
| `POST /verify-model`     | `{ model? }` checks a model id against OpenAI (rate limited).                                                                                                                                                                                             |

### Requests and validation

Strings are sent in chunks of 80 per Responses API request, one request at a time, each with a 90 s timeout, `store: false` and a strict JSON schema listing exactly the requested keys (plural keys list the target language's CLDR categories). Instructions ask the model to keep every `{placeholder}`, rich-text tag and product name, to follow the per-language glossary (`runtime/i18n-glossary.js`) and to stay concise. Every returned string is validated on its own: present, right type, non-empty, the same placeholders, the same balanced tags, no other markup, script or entities, no control characters or new line breaks, a sane length compared with English, protected names unchanged, and the plural categories the language needs. Invalid strings are rejected individually and stay English.

Accepted strings are stored in `.forge-runtime/i18n.sqlite` keyed by `(language, key, source hash)` with the model and time. When English text changes, the hash changes: the old translation is no longer served and the next run sends only the changed strings. Overrides always win and are never overwritten by a new run. Provider errors use the same messages as the Errors review (401 key rejected, 403 no access, 404 model not found, 429 rate limit or quota, 5xx provider problem); the key is never written to a response, log or the database.

## Conversion procedure

1. Read [the conversion guide](I18N_CONVERSION_GUIDE.md) and the file.
2. `npm run i18n:scan -- src/File.jsx` to list strings.
3. Wrap each string with `t`, `tp` or `<T>` using the file's namespace; never change behaviour, values or layout.
4. `npm run i18n:check -- src/File.jsx` and `npm run i18n:scan -- src/File.jsx` (expect 0).
5. Run the file's tests; patch test loaders that strip or rewrite imports (see the guide).
6. After a batch: `npm run i18n:extract`, `npm run i18n:check`, `node --test test/i18n-*.test.js`, `npm run build`.

## Tests

`node --test test/i18n-core.test.js test/i18n-tools.test.js test/i18n-service.test.js test/i18n-ui.test.js` covers the store, plurals, interpolation, fallback, stale sources, RTL, formatters, the pseudo-locale, getters for module-scope labels, that every extracted English default renders unchanged without a provider, the extractor and scanner on fixtures in `test/fixtures/i18n/`, the service against a fake OpenAI server on loopback (preview equals sent, rejection of client-supplied text and hostile keys, per-string validation, chunking, cache and stale detection, override precedence, reset and delete, no key, local provider, model checks, 401/404/429/5xx, cancel, key never in a response), and the provider, `<T>`, field help with translated labels, the language menu and the translate dialog (focus trap, Escape, live progress, report) in jsdom. They do not call the real OpenAI API or judge translation quality.

## Performance

Catalogs are per namespace JSON (a few KB each) and load once per language; English loads nothing. Each `t()` call is a map lookup plus interpolation. The reverse map used by field help holds at most 4,000 entries and is cleared on language change. Translated pages briefly show English while their namespace loads.
