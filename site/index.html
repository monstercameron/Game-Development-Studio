Game development studio

Make the pieces of your game.

Forge brings image, music, sound, video, voice, 3D, world and motion workflows into a React interface backed by a durable render queue. Keep each game’s assets together, inspect local engine health, and connect agents through HTTP and MCP.

Install guide See the 16 models

Built and tested on NVIDIA RTX Spark · native Windows on ARM64

Early-stage The app and queue start without model weights, but rendering needs separately installed models, native engines and, for some adapters, companion applications. A fresh clone is not a one-command AI environment.

  • 16models, plus supporting checkpoints
  • 13engine services on fixed loopback ports
  • 1durable, sequential render queue in SQLite
  • 2026-07-28MCP protocol, over Streamable HTTP or stdio
  • Node 24+React 19 · Vite 6 · Express 5 · Electron
  • MITsource license; models keep their own terms

Hardware

Built on NVIDIA RTX Spark.

Forge is developed and tested on an NVIDIA RTX Spark N1X system: a Blackwell GPU with 6,144 cores and 96 GiB of GPU memory (98,304 MiB as reported by the driver), running Windows 11 on ARM64 natively, with no WSL and no CPU inference. Every Tested status on this page was measured on that one machine, and its memory limits are why Forge loads one model at a time and checks GPU memory before each render.

Other hardware has not been validated to the same level. The figures beside this text are single runs on this machine, not benchmarks. How much the installed model weights add up to, next to this memory, is in Model weight capacity.

  • 96 GiBGPU memory available to the engines
  • 21 sQwen Image 2.1, 1024 × 1024, 12 steps (warm)
  • 70 sTRELLIS.2 textured model, 512 pipeline
  • 20 sHY-Motion, 3 s clip, 50 steps
  • 9 sStable Audio 3, 5 s sound effect

What Forge is

One local studio, many engines.

Forge is an early-stage integration project. It is a project-centred interface for creating, organizing and iterating on game assets, running on your own machine. You create a project, open a workspace, pick compatible project assets as inputs, and add work to one render queue. Results are saved back into the project’s folders.

Behind the interface, a supervised local service starts model engines on demand, checks GPU and system memory before loading or rendering, and keeps engines in isolated processes where supported. The same capabilities are available to scripts over a local HTTP API and to agents over the Model Context Protocol.

Availability varies by model, platform, installed dependencies and granted access. A present file or reachable service does not establish a working GPU render.

Made for

  • Game makers with an NVIDIA GPU who want image, audio, video, 3D, world and motion workflows next to their project files.
  • Agents and scripts that drive the studio through HTTP and MCP tools.
  • Maintainers comfortable restoring native runtimes, Python environments and companion apps.

Not yet for

  • Anyone expecting a one-command, clean-machine AI installer.
  • Model inference on macOS or Linux, which has not been tested.
  • Exposure to an untrusted network: it is a local, loopback service.

A closer look

Projects, panels and a library.

Workspaces

Places to work.

Each panel has its own path (such as /images, /3d, /assets or /models), and Back, Forward and refresh restore the view. In the creation panels, Add to render queue creates a durable job; Save as a draft instead keeps an editable browser draft.

  1. Images

    Generate characters, scenes and game art from a prompt and up to 10 optional reference images, with multi-reference edits, transparent output and variations. Override width, height (multiples of 32) and sampling steps.

    Qwen Image 2.1

  2. 3D models

    Turn a reference image into an untextured GLB shape with Hunyuan3D 2.1, optionally with a PBR texture pass, or make a textured GLB with TRELLIS.2 from a transparent PNG or WebP. Convert results to GLB, glTF, OBJ, PLY or STL.

    Hunyuan3D 2.1 · TRELLIS.2

  3. Worlds

    Generate an environment from text, one image or a 360° panorama with WorldGen (splat PLY or GLB mesh), or reconstruct a Gaussian-splat scene from 1–8 views with HY-World 2.0. Splats open in an interactive preview; panorama meshes have an inside view.

    WorldGen · HY-World 2.0

  4. Character motion

    Text-to-motion as a 30 fps BVH skeleton with HY-Motion 1.0, and keyframe-conditioned transitions between SOMA poses with MotionBricks. Rigging and retargeting are not connected.

    HY-Motion 1.0 · MotionBricks

  5. Video

    Animate 1–9 reference images, with optional reference videos and audio, into short WebM clips. Convert any video to MP4 or GIF. First- and last-frame modes need an optional checkpoint that is not installed.

    MiniMax H3 Ref2VA

  6. Music

    Create music from a style and lyrics (use [Instrumental] for none), extend a track, re-synthesize it with a new seed, or score a melody. Duration, steps, guidance, negative style and title controls.

    YuE2

  7. Sound effects

    Generate sound effects and ambient audio from a prompt. Start from an existing sound to make a variation, replace a region, or continue it. Requires gated model access.

    Stable Audio 3

  8. Voices

    Turn dialogue into speech with nine preset voices, a voice designed from a description, or a cloned voice from a 3–30 second clip (you confirm you have the right to use it). Transcribe English live from a microphone or from audio files up to two minutes and 25 MiB.

    Qwen3-TTS · Nemotron ASR

  9. Segmentation

    Describe an object in a PNG, JPEG or WebP image and save a transparent cutout, mask, outline or cropped image to the project. Choose the best, largest or top-N matches.

    SAM 3.1

  10. Game logic

    Send game state with a choice, score or yes/no questions (several per request) and get a structured decision back for a game character.

    Mammoth-1

  11. Chat

    Streamed conversations with text, JSON or strict JSON-schema replies, sampling controls and thinking levels, with project-scoped browser history. OpenAI-compatible servers also work.

    Qwen3.8-27B

  12. Vegetation

    Grow 20 tree, shrub and cactus species to GLB with SeedThree, on the CPU. Controls come from SeedThree’s own schema, and the design can be saved as a SeedThree preset.

    SeedThree

  13. Megascans

    Browse a cached catalog of free Quixel Megascans 3D models from Fab and download a file into a project, after you accept its licence once.

    Built; live download check pending

  14. Asset library

    Search and filter by generation details, preview, rate, keep, rename and download. Reuse settings queues the same request again. Deletion goes to recoverable project trash. Convert images, audio and 3D models to new copies.

    PNG · JPG · WebP · GIF · WAV · MP3 · FLAC · OGG · MP4 · WebM · GLB · glTF · FBX · BVH · OBJ · PLY · STL

  15. Models & services

    See GPU memory, managed model sizes and observed engine status. Start services, load after a memory check, offload idle workers, force stop, or permanently remove.

    Shared models are protected from removal

  16. Diagnostics

    Server address, port, process ID, Node version and start time; filter, pause and copy live logs from the studio, browser and engines.

    Logs may contain prompts and local paths

  17. Errors review

    Captures browser, queue, server and engine errors with redaction, copy buttons and fingerprints for repeats. An optional GPT fix suggestion and GitHub issues are described under Features.

    Unit and end-to-end tests use fakes

Features

What the studio does now.

Each item carries its state. Tested ran on the real engine or service on this machine. Built is in the app and covered by tests or an isolated copy, but not yet exercised end to end on the real engine. Pending is the open check named in the item. Nothing here is a mock or a disabled control.

Asset metadata and Reuse

Built

Each project keeps generation details for every asset (model, prompt, settings, seed and timings) in its own SQLite database. Search by those details, and use Reuse settings to queue the same request again.

Render queue page

Built

Renders are grouped as Processing, Waiting in line, Needs attention, Failed and Finished. Failed rows can be dismissed. Queue timing shows in the header on every page.

Reordering the waiting line

Built; checked on an isolated copy of the studio

Move a waiting render with Run next, the up and down buttons, or a keyboard-operable drag handle. Running, finished and interrupted renders cannot be moved, and a render that uses another render’s output stays after it.

Queue chaining

Built

A job can wait for an earlier job’s output. For example, remove a background with SAM 3.1 before a 3D render, or generate an image with Qwen Image before a 3D render. Forge places the dependent job right after the one it needs.

One engine at a time

Built

Loads are admitted one engine at a time. Admission checks free GPU memory against each model’s size and refuses ambiguous multi-GPU readings. A finished first model in a chain is unloaded, and a soft host-RAM check warns before a load starves Windows. Each engine has start, load, offload and stop controls.

Interface

Built

Inline help beside parameters, a compact side menu, a mini player (never, once or loop), a 3D viewer, mobile layouts, and hidden engine consoles.

Error review and fix suggestions

Pending real OpenAI and GitHub

Captures browser, queue, server and engine errors, redacts paths and secrets, and groups repeats. A GPT fix suggestion is sent only after you preview the request and choose to send it. GitHub issues are offered only for fixes you mark as working. The flows are unit and end-to-end tested with fakes; they have not yet been exercised with the real OpenAI or GitHub services.

AI assist settings

Built

The OpenAI key is stored encrypted with your Windows account, and each feature has its own model id. The defaults gpt-6.1-sol and gpt-6-luna are names you supplied; they may not exist for your key. Check model asks OpenAI whether the id is valid.

Agents over MCP

Built

An MCP server exposes the queue, assets, asset metadata and models over Streamable HTTP or the stdio bridge. Destructive actions are guarded, and agents are told to ask you first.

Native Windows only

Tested on the target machine

Windows ARM64 with an NVIDIA Blackwell GPU, run natively without WSL. Inference is GPU-only: Forge does not fall back to CPU inference. CPU work is limited to preprocessing and file operations.

  • No safe idle-stop guard; Force stop interrupts a response. OpenAI and other compatible providers can be configured separately — a cloud request sends its conversation to that provider.

How this was measured

Sizes were measured on 2026-11-08 by tools/model-capacity.mjs. It walks every folder under the checkout’s models folder without following links, adds up the size of each regular file, and assigns each folder to one row of the table through a mapping written in the script. The script fails when a folder over 100 MiB is not mapped, so a new model cannot be left out. Sizes are file sizes, so they exclude filesystem overhead and are not parameter counts.

NTFS can give one file several names (hard links). Each such file is counted once, in the model row that owns it. Forge’s Models page and its storage scan add up every name, so they can report more bytes than the files really occupy.

The running studio’s own storage scan reported 381.48 GiB for the same models folder; this table totals 363.70 GiB. The difference is 18.08 GiB of hard-linked names that the studio scan counts twice, offset by 0.30 GiB in a folder the studio scan does not cover (no bytes are left unexplained).

3 of the counted files (9.85 GiB) also have hard links outside the models folder. They are counted here, but deleting them from the models folder would not free that space.

Not measured: parameter counts, compressed size, GPU memory used by a loaded model, or duplicate content stored as separate copies.

Architecture

Supervised, isolated, local.

server.js supervises an HTTP host in a separate process. That host supervises a runtime process that runs the durable SQLite queue and a GPU-monitor worker thread. Engine processes are isolated from the HTTP and queue processes, and the main supervisor keeps handles to the engines it started, so an HTTP-host restart does not give up ownership.

Engine pattern

A Python backend loads and runs the model, a worker owns the local HTTP service and busy state, preparation code checks resources and starts or loads it, and a job adapter moves inputs and outputs through the durable queue. Existing companion apps keep their own APIs.

Process recovery

HTTP and runtime supervisors retry failed starts with backoff. Unexpected exits of services started by the current runtime are retried up to three times, without automatic model loading. On Windows, a restarted supervisor can re-adopt a verified TRELLIS.2 worker; other engines are not yet adopted this way.

Honest status

A port answering is not proof of the expected engine. Forge checks each status response against the engine it expects before reporting it reachable; otherwise the service is shown as unverified or unavailable.

Render queue

One queue that remembers.

Image, music, sound-effect, video, voice, Hunyuan shape, SAM segmentation, HY-Motion and MotionBricks jobs (plus TRELLIS.2 and world renders) run sequentially and are stored in .forge-runtime/jobs.sqlite. Queue leases and accepted remote IDs keep a crash from silently submitting duplicate work.

  1. 01

    Queued

    Waiting jobs can be cancelled. Image, video and BVH inputs are snapshotted into the project for recovery and retries.

  2. 02

    Preparing

    The engine starts on demand; GPU and system memory are checked before loading. If short, Forge may stop one verified idle, Forge-managed worker, then re-check.

  3. 03

    Accepted

    The engine accepts the job and its remote ID is recorded. Render timing starts here.

  4. 04

    Saved

    Output is written atomically to the project’s matching asset folder, with render history kept for reruns and refinement.

Interrupted

If a crash makes a submission uncertain, the queue stops on an interrupted item instead of resubmitting. Check the engine’s own queue and history, then resolve it. Later jobs wait until you do.

Survives restarts

A job with a known remote ID resumes monitoring after a runtime restart. Completed files from the Hunyuan3D, SAM, HY-Motion, MotionBricks and Qwen3-TTS workers can be recovered without reloading the model. Model-load barriers persist too.

Retries reuse work

Retrying a failed job with a known engine job ID rechecks that job rather than rendering again. Submit a new request with a different seed for a new variation. Running jobs cannot yet be cancelled from Forge.

Estimates, labelled

Exact estimates use completed jobs with matching settings; nearby settings give a result marked rough. Without suitable history the studio says the time is unknown instead of inventing one.

Install

Two layers, installed deliberately.

Forge has a web app and local model engines. The installer sets up the web app and can download selected model files, but several engines still depend on separate Windows applications, native CUDA packages or Python environments. Run these from PowerShell in the cloned repository.

  1. Inspect first — nothing is downloaded

    -CheckOnly reports prerequisites without changing them; -ListModels lists every model ID, source and location; -Plan prints intended downloads. 

    powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -CheckOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -ListModels
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Plan -Models worldgen,hy-world

  2. Install and launch the web app

    The installer runs npm ci when node_modules is missing, then builds. The app can start with no model files. 

    powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-server.ps1

    Open http://127.0.0.1:5173, or run start-desktop.cmd for the desktop window. Starting the studio does not load model weights.

  3. Download only the models you need

    Install the Hugging Face CLI, request access for gated models and sign in with hf auth login. Never put tokens in a command or repository file. Downloads go to a new staging folder; no existing model is changed. 

    # Preview the exact sources first.
.\install.ps1 -SkipApp -Plan -Models asr,tts

# Download to a new, separate staging folder.
.\install.ps1 -SkipApp -Models asr,tts

# Or install supported model folders after staging and checks.
.\install.ps1 -SkipApp -Models asr,tts -Activate

    -Activate is available for worldgen, 3d-hunyuan, motion-hy, motion-bricks, tts, asr and segmentation. It installs model files only and refuses to replace an existing target.

  4. Restore each engine’s environment

    Python environments, companion apps and native runtimes are separate dependencies. Follow the installation guide, model sources and Windows ARM64 notes.

  5. Verify, one small render at a time

    Open Models & services and Diagnostics. A reachable service or present file does not prove a model is loaded; run one small render per installed workflow and inspect the asset. 

    powershell -NoProfile -ExecutionPolicy Bypass -File .\stop-server.ps1
# Port 5173 busy? Use the same port to start and stop.
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-server.ps1 -Port 5199

Security & privacy

Local by default.

  • Loopback only

    The unified service binds to 127.0.0.1. Engine addresses are fixed to loopback, and a configured engine URL must be a local HTTP origin. It is not a production authentication or remote-access system.

  • Encrypted API keys

    OpenAI and Hugging Face keys saved in Studio settings are encrypted with the Windows Data Protection API under the current user, stored in a local SQLite database, and never returned to the browser.

  • Tokens stay out of logs

    Keys and tokens are passed to helpers over stdin rather than on command lines, and are not written to queue state, MCP calls or Forge logs. Never put an API key in MCP arguments.

  • Review logs before sharing

    Known secret patterns are redacted on a best-effort basis in the API and UI, but logs can still contain prompts and local paths. The raw log file is not redacted.

  • Your microphone, locally

    Microphone access is requested only when you start recording and released on stop. Audio is sent only to the local speech service.

  • Cloud is opt-in

    A cloud chat request sends its conversation to that provider. Prompts, credentials and uploaded files are never placed in shareable URLs.

Other processes running as your Windows user can potentially use that user’s credentials. Review the security implications before exposing the server to another machine.

FAQ

Straight answers.

Can I download Megascans models?

The portal can browse a cached catalog and download a file into a project after you accept Fab’s terms and the listing’s licence yourself. The download path is built, but a live download through the new code is still pending a check.

Does vegetation need a GPU?

No. SeedThree runs on the CPU and makes flat-coloured GLB models. It is procedural generation, not a neural model, and it has no textures or wind animation.

Is MiniMax H3 video reliable enough to rely on?

No. It rendered on the real engine, but intermittent engine crashes failed 2 of 6 default renders, so it is experimental. Retry submits a fresh attempt.

Will cloning the repository give me working AI models?

No. A fresh clone can run the web application after JavaScript dependencies are installed, but it cannot reproduce the local inference stack by itself. Weights, native runtimes, Python environments and some companion apps are installed separately.

Does it work on macOS or Linux?

Shell launchers are included and syntax checked, but macOS and Linux model integration has not been verified end to end. The local GPU integrations are Windows-specific and not automatically portable.

Is TRELLIS.2 ready to use?

Yes, for the tested workflows. All four pipelines (512, 1024, 1024 cascade and 1536 cascade) rendered on the real engine on this machine and produced textured GLB files with WebP textures. It runs as a native Windows ARM64 port; upstream documents Linux support only.

Can it rig or retarget my characters?

No. HY-Motion and MotionBricks produce BVH motion and are experimental; automatic character rigging and retargeting are not connected.

Can I clone a voice?

Yes, with a 3–30 second clip and your confirmation that you have the right to use the voice. You type the exact words spoken in the clip; Forge does not transcribe it and records the transcript, not the audio. Cloning and designed voices use optional checkpoints that are staged separately.

What happens if the studio crashes mid-render?

Jobs with a known remote ID resume monitoring after restart, and some workers’ completed files can be recovered. If the submission is uncertain, the job is marked interrupted and blocks the queue until you check the engine and resolve it, so work isn’t silently duplicated.

Will a render download missing model files?

No. Forge does not download missing model files during a render. Downloads happen only when you run the installer or a documented downloader deliberately.

How much GPU memory do I need?

It depends on the model. The catalog lists estimates, from about 4 GiB to load Nemotron ASR up to a conservative ~48 GiB budget for Qwen Image 2.1. These are uncalibrated estimates and snapshots, not reservations; Windows commit memory matters too.

Can I reach it from another computer?

It is intended for use on the same computer and binds to loopback. Do not expose the development server to an untrusted network; it is not a remote-access system.

Can an agent delete my files?

Deleted project assets go to recoverable trash. Permanent model deletion, emptying project trash and force stop each need their own explicit confirmation, and the MCP guide tells agents to ask the user before destructive actions.
