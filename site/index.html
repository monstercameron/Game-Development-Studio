Game development studio

Make the pieces of your game.

Forge brings image, music, sound, video, voice, 3D, world and motion workflows into a React interface backed by a durable render queue. Keep each game’s assets together, inspect local engine health, and connect agents through HTTP and MCP.

Install guide See the 15 models

Early-stage The app and queue start without model weights, but rendering needs separately installed models, native engines and, for some adapters, companion applications. A fresh clone is not a one-command AI environment.

  • 15catalog models, plus supporting checkpoints
  • 13engine services on fixed loopback ports
  • 1durable, sequential render queue in SQLite

What Forge is

One local studio, many engines.

Forge is an early-stage integration project. It is a project-centred interface for creating, organizing and iterating on game assets, running on your own machine. You create a project, open a workspace, pick compatible project assets as inputs, and add work to one render queue. Results are saved back into the project’s folders.

Behind the interface, a supervised local service starts model engines on demand, checks GPU and system memory before loading or rendering, and keeps engines in isolated processes where supported. The same capabilities are available to scripts over a local HTTP API and to agents over the Model Context Protocol.

Availability varies by model, platform, installed dependencies and granted access. A present file or reachable service does not establish a working GPU render.

Made for

  • Game makers with an NVIDIA GPU who want image, audio, video, 3D, world and motion workflows next to their project files.
  • Agents and scripts that drive the studio through HTTP and MCP tools.
  • Maintainers comfortable restoring native runtimes, Python environments and companion apps.

Not yet for

  • Anyone expecting a one-command, clean-machine AI installer.
  • Verified macOS or Linux model inference.
  • Exposure to an untrusted network: it is a local, loopback service.

Workspaces

Fourteen places to work.

Each panel has its own path (such as /images, /3d, /assets or /models), and Back, Forward and refresh restore the view. In the creation panels, Add to render queue creates a durable job; Save as a draft instead keeps an editable browser draft.

  1. Images

    Generate characters, scenes and game art from a prompt and up to 10 optional reference images. Override width, height (multiples of 32) and sampling steps.

    Qwen Image 2.1

  2. 3D models

    Turn a reference image into an untextured GLB shape, or queue an experimental textured model from a transparent PNG or WebP.

    Hunyuan3D 2.1 · TRELLIS.2 experimental

  3. Worlds

    Generate an environment from text, one image or a 360° panorama, or reconstruct a Gaussian-splat scene from 1–8 views. Exports PLY with an interactive splat preview.

    WorldGen · HY-World 2.0

  4. Character motion

    Text-to-motion as a 30 fps BVH skeleton, and SOMA pose-to-pose transitions from BVH files. Rigging and retargeting are not connected.

    HY-Motion 1.0 · MotionBricks experimental

  5. Video

    Animate 1–9 reference images into short WebM clips, with H3’s supported 8, 12, 20 or 30 sampling steps.

    MiniMax H3 Ref2VA

  6. Music

    Create music from a style and lyrics (use [Instrumental] for none), with duration, steps, guidance, negative style and title controls.

    YuE2

  7. Sound effects

    Generate sound effects and ambient audio from a prompt with custom duration and generation steps. Requires gated model access.

    Stable Audio 3

  8. Voices

    Turn dialogue into speech with nine preset speakers, and transcribe English live from a microphone or from audio files up to two minutes and 25 MiB.

    Qwen3-TTS · Nemotron ASR

  9. Segmentation

    Describe an object in a PNG, JPEG or WebP image and save a transparent cutout or mask to the project’s masks/ folder.

    SAM 3.1

  10. Game logic

    Send game state with a choice, score or yes/no question and get a structured decision back for a game character.

    Mammoth-1

  11. Chat

    Streamed conversations with text, JSON or strict JSON-schema replies, thinking effort, and project-scoped browser history. OpenAI-compatible servers also work.

    Qwen3.8-27B

  12. Asset library

    Search, filter, sort, preview, rate, keep, rename and download. Deletion goes to recoverable project trash. Convert images and audio to new copies.

    PNG · JPG · WebP · GIF · WAV · MP3 · FLAC · OGG · MP4 · WebM · GLB · glTF · FBX · BVH

  13. Models & services

    See GPU memory, managed model sizes and observed engine status. Start services, load after a memory check, offload idle workers, force stop, or permanently remove.

    Shared models are protected from removal

  14. Diagnostics

    Server address, port, process ID, Node version and start time; filter, pause and copy live logs from the studio, browser and engines.

    Logs may contain prompts and local paths

Architecture

Supervised, isolated, local.

server.js supervises an HTTP host in a separate process. That host supervises a runtime process that runs the durable SQLite queue and a GPU-monitor worker thread. Engine processes are isolated from the HTTP and queue processes, and the main supervisor keeps handles to the engines it started, so an HTTP-host restart does not give up ownership.

Engine pattern

A Python backend loads and runs the model, a worker owns the local HTTP service and busy state, preparation code checks resources and starts or loads it, and a job adapter moves inputs and outputs through the durable queue. Existing companion apps keep their own APIs.

Process recovery

HTTP and runtime supervisors retry failed starts with backoff. Unexpected exits of services started by the current runtime are retried up to three times, without automatic model loading. On Windows, a restarted supervisor can re-adopt a verified TRELLIS.2 worker; other engines are not yet adopted this way.

Honest status

A port answering is not proof of the expected engine. Forge checks each status response against the engine it expects before reporting it reachable; otherwise the service is shown as unverified or unavailable.

Render queue

One queue that remembers.

Image, music, sound-effect, video, voice, Hunyuan shape, SAM segmentation, HY-Motion and MotionBricks jobs (plus experimental TRELLIS.2 and world renders) run sequentially and are stored in .forge-runtime/jobs.sqlite. Queue leases and accepted remote IDs keep a crash from silently submitting duplicate work.

  1. 01

    Queued

    Waiting jobs can be cancelled. Image, video and BVH inputs are snapshotted into the project for recovery and retries.

  2. 02

    Preparing

    The engine starts on demand; GPU and system memory are checked before loading. If short, Forge may stop one verified idle, Forge-managed worker, then re-check.

  3. 03

    Accepted

    The engine accepts the job and its remote ID is recorded. Render timing starts here.

  4. 04

    Saved

    Output is written atomically to the project’s matching asset folder, with render history kept for reruns and refinement.

Interrupted

If a crash makes a submission uncertain, the queue stops on an interrupted item instead of resubmitting. Check the engine’s own queue and history, then resolve it. Later jobs wait until you do.

Survives restarts

A job with a known remote ID resumes monitoring after a runtime restart. Completed files from the Hunyuan3D, SAM, HY-Motion, MotionBricks and Qwen3-TTS workers can be recovered without reloading the model. Model-load barriers persist too.

Retries reuse work

Retrying a failed job with a known engine job ID rechecks that job rather than rendering again. Submit a new request with a different seed for a new variation. Running jobs cannot yet be cancelled from Forge.

Estimates, labelled

Exact estimates use completed jobs with matching settings; nearby settings give a result marked rough. Without suitable history the studio says the time is unknown instead of inventing one.

API & MCP

Built for people and agents.

Forge provides local HTTP APIs and MCP tools for model discovery, project and asset operations, queue control and supported creation workflows. The same MCP tools are served over Streamable HTTP at http://127.0.0.1:5173/mcp and through the stdio bridge in runtime/mcp.js; both use one shared tool registry and require the 2026-07-28 MCP protocol. Older handshakes are rejected.

GET /api/models returns the shared model catalog: each model’s purpose, inputs, outputs, engine, related MCP tools and the latest service and storage observations. If the runtime is unavailable, the static catalog is still returned with runtimeAvailable: false.

PowerShell · model catalog
Invoke-RestMethod 'http://127.0.0.1:5173/api/models'
Start the stdio bridge (Studio must be running) 
npm run mcp

Requirements

Where it runs today.

Platform support, as documented
Platform Status Notes
Windows ARM64 + NVIDIA GPU Targeted The observed installation was assembled on an NVIDIA RTX Spark N1X, natively, without WSL.
Other Windows hardware Not validated Other platforms and hardware have not been validated to the same level.
macOS and Linux Unverified Shell launchers are syntax checked, but model integration has not been verified end to end. Keep-awake is Windows-only.
Multiple GPUs Refused Memory admission needs a single identifiable NVIDIA GPU and refuses ambiguous multi-GPU readings.

You will need

  • Node.js 24 or later and npm (pnpm is a supported alternative).
  • An NVIDIA GPU and compatible driver. Memory and storage needs depend on the model and settings; model files and working memory can each take many gigabytes.
  • Enough free Windows commit memory as well as GPU memory — they are separate measurements.
  • Model weights, native runtimes, credentials and companion apps, installed separately. Some model repositories require access approval.

Install

Two layers, installed deliberately.

Forge has a web app and local model engines. The installer sets up the web app and can download selected model files, but several engines still depend on separate Windows applications, native CUDA packages or Python environments. Run these from PowerShell in the cloned repository.

  1. Inspect first — nothing is downloaded

    -CheckOnly reports prerequisites without changing them; -ListModels lists every model ID, source and location; -Plan prints intended downloads. 

    powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -CheckOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -ListModels
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Plan -Models worldgen,hy-world

  2. Install and launch the web app

    The installer runs npm ci when node_modules is missing, then builds. The app can start with no model files. 

    powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-server.ps1

    Open http://127.0.0.1:5173, or run start-desktop.cmd for the desktop window. Starting the studio does not load model weights.

  3. Download only the models you need

    Install the Hugging Face CLI, request access for gated models and sign in with hf auth login. Never put tokens in a command or repository file. Downloads go to a new staging folder; no existing model is changed. 

    # Preview the exact sources first.
.\install.ps1 -SkipApp -Plan -Models asr,tts

# Download to a new, separate staging folder.
.\install.ps1 -SkipApp -Models asr,tts

# Or install supported model folders after staging and checks.
.\install.ps1 -SkipApp -Models asr,tts -Activate

    -Activate is available for worldgen, 3d-hunyuan, motion-hy, motion-bricks, tts, asr and segmentation. It installs model files only and refuses to replace an existing target.

  4. Restore each engine’s environment

    Python environments, companion apps and native runtimes are separate dependencies. Follow the installation guide, model sources and Windows ARM64 notes.

  5. Verify, one small render at a time

    Open Models & services and Diagnostics. A reachable service or present file does not prove a model is loaded; run one small render per installed workflow and inspect the asset. 

    powershell -NoProfile -ExecutionPolicy Bypass -File .\stop-server.ps1
# Port 5173 busy? Use the same port to start and stop.
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-server.ps1 -Port 5199

Security & privacy

Local by default.

  • Loopback only

    The unified service binds to 127.0.0.1. Engine addresses are fixed to loopback, and a configured engine URL must be a local HTTP origin. It is not a production authentication or remote-access system.

  • Encrypted API keys

    OpenAI and Hugging Face keys saved in Studio settings are encrypted with the Windows Data Protection API under the current user, stored in a local SQLite database, and never returned to the browser.

  • Tokens stay out of logs

    Keys and tokens are passed to helpers over stdin rather than on command lines, and are not written to queue state, MCP calls or Forge logs. Never put an API key in MCP arguments.

  • Review logs before sharing

    Known secret patterns are redacted on a best-effort basis in the API and UI, but logs can still contain prompts and local paths. The raw log file is not redacted.

  • Your microphone, locally

    Microphone access is requested only when you start recording and released on stop. Audio is sent only to the local speech service.

  • Cloud is opt-in

    A cloud chat request sends its conversation to that provider. Prompts, credentials and uploaded files are never placed in shareable URLs.

Other processes running as your Windows user can potentially use that user’s credentials. Review the security implications before exposing the server to another machine.

Development & quality

Test the right layer.

PowerShell
npm ci
npm run dev                 # Vite development server
npm test                    # JavaScript tests
npm run build               # Production frontend build
npm run lint                # ESLint
npm run format:check        # Prettier

Python checks use Ruff in a separate .venv-dev environment (Python 3.12) so developer tools never land in a model’s environment.

The JavaScript suite (node --test) covers queue persistence and recovery, lease fencing, model-load barriers, GPU-memory admission, worker protocols, project assets and trash, model inventory and removal, HTTP, and MCP.

A native TRELLIS component suite checks CuMesh, FlexGEMM, O-Voxel, nvdiffrast, OpenCV preprocessing and sparse SDPA on small inputs. Separate real-model checks load gigabytes of weights; none of them generates a complete TRELLIS.2 asset.

Tests that use fake engines establish protocol behaviour; they do not prove real GPU generation or visual and audio quality. ESLint and Ruff don’t verify inference, security, accessibility or output quality either.

Built with React 19, Vite 6, Express 5, three.js, Electron, the MCP TypeScript SDK and zod, with Lucide icons.

FAQ

Straight answers.

Will cloning the repository give me working AI models?

No. A fresh clone can run the web application after JavaScript dependencies are installed, but it cannot reproduce the local inference stack by itself. Weights, native runtimes, Python environments and some companion apps are installed separately.

Does it work on macOS or Linux?

Shell launchers are included and syntax checked, but macOS and Linux model integration has not been verified end to end. The local GPU integrations are Windows-specific and not automatically portable.

Is TRELLIS.2 ready to use?

Not yet. It is an experimental queue workflow on a native Windows ARM64 port. The pipeline has loaded and its DINOv3 encoder has run on CUDA, but a complete textured render and its memory budget remain unverified.

Can it rig or retarget my characters?

No. HY-Motion and MotionBricks produce BVH motion and are experimental; automatic character rigging and retargeting are not connected.

Can I clone a voice?

No. The integrated Qwen3-TTS CustomVoice model uses nine preset speakers with optional voice direction. Voice cloning and voice design need other models and are not connected.

What happens if the studio crashes mid-render?

Jobs with a known remote ID resume monitoring after restart, and some workers’ completed files can be recovered. If the submission is uncertain, the job is marked interrupted and blocks the queue until you check the engine and resolve it, so work isn’t silently duplicated.

Will a render download missing model files?

No. Forge does not download missing model files during a render. Downloads happen only when you run the installer or a documented downloader deliberately.

How much GPU memory do I need?

It depends on the model. The catalog lists estimates, from about 4 GiB to load Nemotron ASR up to a conservative ~48 GiB budget for Qwen Image 2.1. These are uncalibrated estimates and snapshots, not reservations; Windows commit memory matters too.

Can I reach it from another computer?

It is intended for use on the same computer and binds to loopback. Do not expose the development server to an untrusted network; it is not a remote-access system.

Can an agent delete my files?

Deleted project assets go to recoverable trash. Permanent model deletion, emptying project trash and force stop each need their own explicit confirmation, and the MCP guide tells agents to ask the user before destructive actions.
